# 불꽃 (bulkkot)

한강 불꽃축제가 **실제로 보이는 자리**를 기하로 찾는다.

그늘 계산기는 태양의 방위·고도와 건물 높이로 그림자를 접는다. 여기서는 그
계산을 뒤집는다. 광원이 무한히 먼 태양이 아니라 2~8km 앞 **유한 거리의 점**이고,
그 점이 시간에 따라 **고도**를 바꾼다는 것만 다르다.

```
그늘 계산      : 태양 → 건물 → 이 자리에 그림자가 지는가?
불꽃 가시성 계산 : 이 자리 → 건물 → 발사 지점 상공 몇 m부터 눈에 들어오는가?
```

## 핵심 개념 하나: 최소 가시 고도

이 도구가 계산하는 값은 결국 하나다.

> **최소 가시 고도(MVA)** — 이 자리에서는 발사면 기준 몇 m 위에서 터져야 보이는가?

이 값 하나가 "명당이냐 아니냐"라는 뭉툭한 질문을 쪼갠다. 용양봉저정공원의 MVA는
104m다. 앞을 막은 노량진 언덕 능선 때문이다. 그래서 개막의 수상 저고도 연출과
원효대교 나이아가라는 **한 발도 보이지 않고**, 300m 넘게 올라가는 피날레는
**전부 보인다**. 태양이 시각에 따라 자리를 옮기듯, 불꽃은 시각에 따라 고도를
옮긴다 — 그래서 한 자리의 가시성은 하나의 점수가 아니라 프로그램 위의 함수다.

```
$ bulkkot explain yongyangbong

    주 바지선 (여의도 앞 한강 중앙)       1.16km    104m 이상  ← 노량진 언덕 능선

  프로그램 진행에 따른 가시율
      0~  8분  개막 수상 저고도 연출           ············   0%  올려각  2.5°

     25~ 30분  원효대교 나이아가라             ············   0%  올려각  2.4°
```

## 쓰는 법

의존성이 없다. 파이썬 3.10 이상이면 그대로 돈다.

```bash
python -m bulkkot rank                 # 후보지 순위
python -m bulkkot rank --hidden        # 이미 유명한 명당은 빼고, 한산함에 가중치
python -m bulkkot explain nodeulseom   # 한 자리를 뜯어보기 (시선 단면 포함)
python -m bulkkot check 37.5117 126.9530 --elev 55   # 임의 좌표
python -m bulkkot scan --step 200 --exclude-known    # 격자로 이름 없는 자리 찾기
python -m bulkkot report --scan -o 관측도.html        # 자립형 HTML 관측도
```

`report` 가 만드는 HTML은 외부 타일 서버도 CDN도 부르지 않는다. 라이브러리
없이 캔버스에 직접 그리는 3D 장면이라 파일 하나로 끝난다. 보기는 셋이다.

- **3D 조감** — 건물은 압출된 덩어리로, 능선은 커튼으로 선다. 드래그로 돌리고
  휠로 당긴다. 선택한 자리에서 불꽃까지 시선이 그어지는데, 초록이면 지금 보이고
  빨강이면 막혔다. 점선은 "겨우 보이기 시작하는 높이"다.
- **이 자리에서 보기** — 카메라를 그 자리의 눈높이에 놓고 발사 지점을 본다.
  하늘에 가로줄이 하나 그이는데, 그 아래로 터지는 것은 보이지 않는다.
  개막 저고도 연출은 줄 아래에서, 피날레는 줄 위에서 터진다.
- **평면도** — 방위와 거리를 확인할 때. 교량·지명·축척·방위표가 있다.

3D의 높이는 기본값 ×2로 부풀렸다. 시선·불꽃·장애물을 **같은 비율로** 늘리므로
가려지고 말고는 그대로다 (z에 대한 선형 변환은 대소 관계를 보존한다).

자리를 누르면 그 자리에서 발사 지점까지의 **시선 단면**도 함께 나온다.

## 계산 방식

관람자의 눈높이에서 발사 지점 **상공**으로 시선을 긋는다. 불꽃은 발사 지점
바로 위에서 터지므로 수평거리 `D`가 고정되고, 시선의 높이는 도착 표고에 대해
선형이다. 따라서 시선에 걸친 장애물 하나하나에 대해

```
필요한 도착 표고 = z_눈 + (장애물_상단 + 곡률보정(s) - z_눈) × D / s
```

를 구하고 그 **최댓값**을 취하면 최소 가시 고도가 한 번에 나온다. 이분 탐색이
필요 없다. 같은 높이라면 가까운 장애물이 더 많은 고도를 요구하므로, 각 건물은
시선이 처음 닿는 지점만 보면 된다.

- **장애물**은 폴리곤(건물)과 폴리라인(능선)을 모두 표고(해발) 기준으로 다룬다.
  지형과 건물을 같은 비교로 처리하려면 이 정규화가 필요하다.
- **지구 곡률과 대기 굴절**(k=0.13)을 반영한다. 8km 시선에서 1~3m 수준이지만,
  강 건너 저고도 연출의 가시 여부를 가르는 경계에서는 이게 답을 뒤집는다.
- **점수**는 기하(보이는 비중·화면 채움·올려각)와 현장(한산함·접근성)을 나눠
  계산하고 항상 분해해서 보여준다. 앞의 셋은 데이터에서 나오고, 뒤의 둘은
  사람이 넣는 값이다.

## 데이터가 결과다

내장된 것은 **씨드 데이터**다. 좌표·건물 높이·프로그램 고도가 모두 근사치이고,
`massing_`으로 시작하는 항목은 시가지를 한 덩어리로 뭉갠 블록이다. 그래서
지금의 순위는 **방법을 보여주는 예시**이지 현장 판단 근거가 아니다.

도구는 그 사실을 숨기지 않는다. 시선이 데이터 범위 밖을 지나면 결과에
`데이터 밖` 표시가 붙는다 — "안 막힌다"가 정말 트여서인지, 그 구간을 아무도
채워 넣지 않아서인지 구분하기 위해서다.

실제로 쓰려면 **[`docs/DATA.md`](docs/DATA.md) 에 무엇을 어디서 받아 어떻게
넣는지 순서대로 적어 두었다.** 국토교통부 건물통합정보(또는 VWorld / Overpass)와
수치표고모델로 갈아끼우면 된다. 어댑터는 이미 들어 있다.

```python
from bulkkot.providers import fetch_overpass
from bulkkot.providers.overpass import to_obstacles_json

obstacles = fetch_overpass((37.49, 126.88, 37.58, 127.05))
json.dump(to_obstacles_json(obstacles), open("mydata/obstacles.json", "w"), ensure_ascii=False)
```

```bash
python -m bulkkot rank --data mydata
```

## 아직 계산하지 않는 것

정직하게 적어 둔다. 아래는 모두 실제 관람 만족도에 영향을 주지만 지금은 모델에
없다.

- **연기와 바람** — 바람이 관람자 쪽으로 불면 후반부가 연기에 잠긴다. 풍향
  예보를 넣어 발사점→관람자 방향과 비교하면 바로 반영할 수 있다.
- **가로수** — 강변 관람의 실질적인 차폐물인데 수관 높이 데이터가 필요하다.
- **수면 반사** — 강이 시선에 들어오면 체감이 크게 달라진다. 하천 폴리곤을
  넣고 시선 교차를 보면 된다.
- **현장 통제** — 축제 당일 폐쇄되는 구역은 매년 다르다. `spots.json` 에
  수동으로 반영하는 수밖에 없다.
- **미세먼지·습도** — 원거리 관람의 대비를 떨어뜨린다.
