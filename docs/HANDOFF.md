## 1. P3009 복구 — 준비 완료, 실행은 대기

**운영 DB 에 접근할 수 없어 실제 상태를 확인하지 못했다.** 추정 복구는 하지 않았다.
대신 격리 PostgreSQL 16 에 실패 상태를 재현해 판단 근거와 복구 절차를 검증했다.
절차는 `docs/recovery/README.md`.

### 확인된 사실 (재현으로)

- 이 마이그레이션은 `ALTER TYPE ... ADD VALUE` 를 포함해 **Prisma 가 트랜잭션 없이
  실행한다.** 그래서 실패해도 앞부분이 그대로 남는다. **부분 적용이 예외가 아니라 기본값이다.**
- 재현 결과 `applied_steps_count` 는 **0** 인데 enum 4종·컬럼 5개·테이블 4개·인덱스 6개·
  FK 6개가 적용돼 있었다. 그 값으로 판단하면 안 된다.
- 부분 적용 상태에서 원본 SQL 을 다시 돌리면 `type "BugStatus" already exists` 로
  또 실패한다. → **부분 적용이면 `resolve --rolled-back` 후 재시도는 답이 아니다.**

### 넘긴 것

| 파일 | 무엇 |
| --- | --- |
| `docs/recovery/01-diagnose.sql` | 읽기 전용. 실행 순서대로 28개 항목의 존재 여부를 내놓아 **어느 문장에서 멈췄는지** 짚는다. 원래 오류(`logs`), 기존 데이터 기준값, 설문별 응답 수도 함께 |
| `docs/recovery/02-forward-fix.sql` | 빠진 것만 채운다. 전부 IF NOT EXISTS/존재 검사라 어느 지점에서 멈췄든 몇 번을 돌리든 같은 결과. 기존 행을 읽지도 바꾸지도 않는다 |
| `docs/recovery/README.md` | 상태별 분기와 실행 순서 |

검증: 부분 적용 DB·빈 DB 양쪽에서 전진 복구 후 카탈로그 **432개 항목이 정상 적용 DB 와
완전 일치**. 3회 반복에도 동일. 데이터 보존 확인(users 3·projects 1·members 1·follows 2·
responses 5·participations 2 그대로). 기존 행의 알림 기본값 전부 `false`.
전진 복구 → `resolve --applied` 로 P3009 가 풀리고 후속 마이그레이션은 대기 상태로 남는 것까지 확인.

### 사용자에게 필요한 것

1. `01-diagnose.sql` 실행 결과 전부 (비밀값 없음)
2. 실패한 배포가 Preview 인지 Production 인지, **Preview 가 운영 DB 를 공유하는지**
3. 복구 가능한 스냅샷 유무

### 복구 전 막아둘 것

`vercel.json` 의 `buildCommand` 가 `prisma migrate deploy && next build` 다.
**Preview 배포도 마이그레이션을 돌린다.** Preview 가 운영 DB 를 공유하면 복구 중에
다른 배포가 끼어든다. 자동 재배포를 멈추고, 풀러를 거치지 않는 직결 주소로 실행한다.
재발 방지안 3가지는 README 5절에 적었다 — 어느 쪽이든 설계 결정이라 손대지 않았다.

## 3. 검증

최종 HEAD(`8f02d59`)에서 1회씩:

```
npx tsc --noEmit          통과
npx eslint .              통과
npx vitest run            184개 통과 (기존 164 → +20)
npm run build             통과
npx playwright test       23개 통과 (기존 14 → +9)
```

DB 통합 검증은 REVIEW.md 지시대로 **기존 Postgres 가 있는 e2e 잡**에서 돈다.
`e2e/` 안의 spec 이라 워크플로 변경 없이 `npm run e2e` 에 포함된다. check 잡에 Postgres 를
추가하지 않았다.

동시성이 실제로 잡히는지도 확인했다 — `FOR UPDATE` 를 빼고 "기존 2건" 케이스를 3회
돌리자 **`공개 증가량 4` 로 깨졌다.** 잠금을 넣으면 전부 통과한다.
경합이라 매번 재현되지는 않는다(3회 중 1회 검출).

새 e2e fixture 는 계정·프로젝트·설문을 매번 새로 만들고 끝나면 지운다.
