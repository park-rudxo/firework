## 구현하며 정한 것 (Astra 확인 요망)

계획에 없던 갈림길 넷. 되돌릴 수 있는 것들이라 일단 정하고 진행했다.

1. **묶음 공개를 `survey_response.revealed` 컬럼으로 고정했다.**
   DECISIONS의 "묶음 구성원을 고정해야 한다"가 맞았다. 조회 시점에 "앞에서 3건"을 다시 고르면, 새 응답이 정렬 순서상 앞에 끼어들 때 이미 공개됐던 것이 사라지고 새 것이 나타난다. 그 차이가 곧 신규 응답을 가리킨다.
   그래서 3의 배수에 닿을 때 감춰둔 것을 한꺼번에 켜고, 한 번 켜진 것은 꺼지지 않는다.
   **대가:** 응답 행에 필드가 하나 늘었다. 덤프를 보면 "아직 안 켜진 두 건 이하가 가장 최근"이라는 사실이 드러난다. 제작자가 화면에서 이미 아는 것과 같은 크기이고, 순번이나 묶음 번호와 달리 전체를 줄 세우지는 못한다. 불리언으로 둔 이유가 그것이다.
   **더 강한 대안:** 설문 종료 후에만 개별 응답 공개. 그러면 컬럼이 필요 없고 증분 노출도 없다. 대신 제작자가 마감까지 자유서술을 못 본다. 바꾸려면 말해달라.

2. **초대 응답 후 화면 이동.** 답한 초대는 목록에서 사라지므로 결과 메시지를 카드 안에 둘 수 없었다(눌렀는데 아무 일도 없어 보인다). 수락하면 그 프로젝트로, 거절하면 `/invitations?done=declined`로 보낸다.

3. **검색 결과에서 후보를 빼지 않는다.** 처음엔 이미 팀원이거나 대기 중인 사람을 목록에서 제외했는데, 그러면 방금 초대한 사람이 사라져 성공했는지 알 수 없다. 목록에 남기고 "수락 대기 중"·"이미 팀원"만 붙인다.

4. **마이그레이션 백필.** `revealed`가 전부 false로 시작하면 이미 3건 이상 모인 설문에서 개별 응답이 통째로 사라진다. 설문마다 3의 배수만큼 열어둔다. 격리 DB에서 5건 → 3건 공개, 2건 → 0건 공개를 확인했다.

## 검증

전부 이 환경에서 직접 돌렸다.

- 타입·린트·빌드 통과. 단위 테스트 **164개 통과**(기존 116 + 48 추가).
- 새 테스트: `team-invitations`(22) · `permissions`(8) · `survey-reveal`(5) · `curation-score`(4) · `anonymity` 확장(9).
- 마이그레이션 두 개를 빈 DB에 처음부터 적용하고 시드까지 통과. 백필 SQL도 따로 확인.
- **E2E 14개 통과.** 로그인이 필요한 흐름을 위해 `e2e/fixtures.ts`를 추가했다 — 세션 행을 만들고 Better Auth가 실제로 읽는 것과 같은 방식으로 서명한 쿠키를 심는다. OAuth 없이 로그인 상태를 만드는 유일한 방법이다.
- **연속 3회 실행 통과.** 계정·프로젝트를 테스트마다 새로 만들고 끝나면 지운다. 지난번 막혔던 두 지점을 다시 확인했다 — 제작자의 처리 상태 선택은 `select[name=status]`로 잡았고(라벨 문구에 의존하지 않는다), 중복 fixture 문제는 남은 데이터가 0건임을 SQL로 확인했다.
- 검증한 흐름: 미승인 초대에 권한 없음 · 등록자 아닌 사람의 팀 화면 거절 · 인증 안 한 계정 미검색 · 수락 후 운영 화면 열림 · 공동 관리자의 팀 화면 거절 · 구독 해제 후 재구독 시 알림 OFF · 버그 접수 → 수정 완료 → 제보자 확인.

## 막혀 있는 것

- **싸피 Mattermost OAuth 앱·전용 봇·DM 권한은 여전히 미확인.** 사람이 확인해야 한다. 설정이 없으면 연결도 발송도 비활성이라 이대로 배포해도 문제는 없다.
- **실제 Mattermost 인증·발송은 검증하지 않았다.** 위와 같은 이유다.
