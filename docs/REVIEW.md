# Claude 수정 지시 — main 병합 전
검토 기준: 2df7a48. 담당: 구현·테스트 Claude / 설계·병합 Astra.
브랜치: claude/firework-reliability-team-invites. 기존 커밋은 재작성하지 말고 아래 3개 커밋을 순서대로 추가한다.

## 결정과 제외 범위
- revealed 불리언을 유지한다. 종료 후 공개로 전환하지 않는다. 제작자에 대한 제한이며 운영자 DB 접근까지 익명을 보장하지 않는다.
- 초대 승인/거절 후 이동과 후보 상태 표시는 승인한다.
- 소유권 이전·OWNER 초대·홈 개편·새 Mattermost 발송 방식은 이번 작업에서 제외.
- check 잡에 Postgres를 추가하지 않는다. 기존 Postgres가 있는 e2e 잡에 DB 통합 검증 단계를 추가한다.

## 커밋 1 — 설문 결과의 차분 노출 차단
대상: features/survey/queries.ts, 결과 화면·안내, 관련 테스트.
현재 getSurveyResults는 자유서술만 revealed로 제한하고 평점·선택 분포는 전체 응답으로 계산한다.
재현: 3건 평점 합계가 9이고 4건 평균이 3.5면 새 점수는 4×3.5−9=5다. 선택 분포 차이도 새 선택을 드러낸다.
조치: 자유서술·평균·분포·선택 집계 모두 동일한 revealed 집합에서 계산한다. 실제 접수 수와 공개 수는 분리 표시하고, 3건 미만 결과 값은 비공개임을 표현한다.
통과: 3→4→5건에서 실제 접수 수 외 모든 답변 기반 결과가 동일. 6건째에 새 묶음 반영. 선택형·다중선택·평점·선택 문항의 무응답도 검증한다.
총 접수 건수 자체는 유지 가능. 단 개별 답변 내용과 연결되는 값은 미공개 응답에서 계산하지 않는다.

## 커밋 2 — 묶음 공개 동시성·기존 데이터 보존
대상: features/survey/actions.ts, 필요시 마이그레이션, DB 통합 테스트.
단순 transaction은 같은 설문 제출을 직렬화하지 않는다. 기존 2건에서 두 트랜잭션이 각각 자기 응답을 넣고 count=3을 보면 각자 묶음을 열어 최종 4건이 공개될 수 있다.
조치: 설문 부모 행의 FOR UPDATE 잠금을 응답 삽입 전에 획득하여 동일 설문 제출을 직렬화한다(Prisma 파라미터 바인딩 사용). 공개되지 않은 응답 기준으로 완성된 3건 묶음을 공개한다. 응답자/시간/순번/묶음 번호는 추가하지 않는다.
통과: 실제 PostgreSQL에서 0·1·2·3건을 시작점으로 동시 제출. 신규 공개 증가량은 3의 배수, 공개된 ID는 유지, 남은 비공개는 0~2건. 같은 사용자의 동시 중복 제출도 응답/참여/응모권이 한 번만 생긴다.
묶음 공개 알림도 커밋된 공개 전환에서 결정한다. 기존 count===3 사후 조회에 따른 알림 중복·누락을 검증한다.
백필 주의: 예전 구현에서 5건 모두 보였는데 3건만 남기면 나중의 재공개로 이미 알려진 응답 2건과 신규 1건이 섞여 신규를 특정할 수 있다. 이미 공개 가능했던 기존 >=3건 설문은 전부 공개 상태를 보존하고, 이후 새 응답 3건씩 공개한다(기존 5→새 1·2건은 그대로 5, 새 3건에서 8). 기존 1·2건은 숨김 유지.
마이그레이션을 실제 공유/운영 DB에 적용했는지 먼저 확인한다. 이미 적용한 SQL은 고치지 않는다. 구분 정보가 없어 기존 공개 집합을 안전하게 복원할 수 없으면 추정하지 말고 그 설문을 임시로 추가 공개하지 않은 채 HANDOFF에 복구 선택지를 적는다.

## 커밋 3 — 초대 대상 인증 ID 고정
대상: features/team/actions.ts, 초대/DB 테스트.
현재 초대는 inviteeMattermostUserId를 저장하지만 승인에서 이 값을 조회·비교하지 않는다. 같은 firework 계정에서 Mattermost A 연결을 해제하고 B를 연결해도 A 대상 초대를 승인할 수 있다.
조치: 승인 트랜잭션에서 현재 userId와 mattermostUserId가 초대의 inviteeId 및 inviteeMattermostUserId 모두와 일치하는지 검증한다. 인증 연결 해제/교체와의 동시 실행도 잠금 또는 동등한 원자성으로 보호한다.
기존 멤버가 있으면 upsert로 역할을 덮어쓰지 말고 거절한다. 승인·취소 경쟁은 최종 상태 하나와 이에 일치하는 멤버십만 남겨야 한다.
통과: A로 초대받고 B로 재연결한 계정 승인 실패, 원래 A 정상 승인, 해제 상태 실패, 타인·중복 승인 실패, 승인/취소 동시 요청, 기존 팀원 역할 보존. 실패 시 멤버십이나 수락 알림이 생기지 않는다.

## 검증·인계
- 각 커밋의 변경과 직접 관련된 테스트를 먼저 돌린다. 최종 HEAD에서 타입·린트·단위·빌드·E2E·실제 PostgreSQL 통합 테스트를 1회 실행한다. 실패/새 변경 없으면 같은 전체 검증을 반복하지 않는다.
- DB 테스트는 기존 e2e 잡의 격리 DB와 고유 fixture를 사용한다. 목 테스트나 PGlite만으로 동시성 통과를 주장하지 않는다.
- HANDOFF에는 3개 커밋 ID, 테스트 명령/결과, 미해결 항목만 기록하고 push. 실제 Mattermost 발송은 여전히 수행하지 않는다.
